# «Парки Москвы» — рабочие заметки

Файл ведётся по ходу работы. Если начинаешь новую сессию — прочитай его первым делом,

## 1. Что за проект

Тестовое задание на вакансию верстальщика в «Энсайн». Нужно сверстать десктопную
версию макета «Развитие парков» (Парки Москвы). Срок — 1 день.

Макет (Figma, из письма заказчика):
`https://www.figma.com/design/WlOFjbgo3bIGkAoXs6d1XS/`

Требования из письма:

- десктоп, сборка с использованием ИИ-инструментов;
- **хедер физически отделён**: топбар (подкасты, поиск, версия для слабовидящих) + меню;
- **футер физически отделён** — те же требования;
- **хлебные крошки** — отдельный блок, не внутри контейнера с динамическим контентом страниц;
- сторонние скрипты для селекторов — только по согласованию, предпочтительно `select2`;
- плагины должны иметь открытые события, чтобы программист мог навесить свои обработчики.

## 2. Как читать макет (PDF)

Figma по ссылке не открывается без токена, поэтому работаем по PDF-экспорту:
`park-layout.pdf`, одна страница 1920 × 9973 px.

Важно: **текст в PDF обведён в кривые** (нет `/BaseFont`), поэтому имена шрифтов,
точные размеры и `letter-spacing` из файла не достаются. Размеры шрифта выводятся
по высоте букв (±1–2 px), цвета и геометрия — точные.

Как получить полосы для измерения:

1. Разрезать PDF по `MediaBox` инкрементальным апдейтом (скрипты `split_pdf_bands.py`,
   `band_events.py` — лежали в рабочей папке агента, воспроизводятся заново).
2. Рендерить полосу в 144 dpi → 2x.
3. Лимит рендерера: 8192 px по стороне и 16 Мп на изображение, поэтому страница
   режется на полосы по ~1100 pt.

Проверка результата: собрать `vite build`, поднять локальный сервер, снять страницу
в headless Chrome в 2x и сравнить с рендером макета по колонкам и вертикальному ритму.

## 3. Стек и структура

- Vite 5 + `vite-plugin-handlebars` + SCSS (`sass`) + Swiper 11.
- Один блок = папка `src/components/<block>/` с `<block>.html` и `_<block>.scss`.
- Подключение разметки: `{{> block}}` в `index.html` или в родительском блоке.
- Подключение стилей: `@use` в `src/styles/main.scss`.
- Переменные: `src/styles/_variables.scss` (`$color-primary: #0d483b`,
  `$color-line: #e1eae8`, `$color-gray: #727874`).
- Контейнер: `.container` — max-width 1920, padding 0 120 → контент 1680.

Проверенные значения из макета: карточка события 402 px, зазор 24, вертикальный
ритм 60, фото 230, плашка «Бесплатно» 24 в высоту с отступами 10, тег 24.

## 8. Известные проблемы

- **Шрифт.** В `_variables.scss` объявлен `PT Root UI`, но `_fonts.scss` пуст и папки
  `src/assets/fonts` нет — всё рендерится Arial. Это главное расхождение с макетом;
  из-за него ширина строк другая, поэтому в заголовках карточек 1 и 4 переносы
  заданы вручную через `<br>`.
- **Ссылка карточки.** Вся карточка обёрнута в `<a>`, поэтому теги-ссылки внутрь
  вставить нельзя (вложенные `<a>` невалидны). Решение: либо оставить карточку
  кликабельной целиком, либо сделать ссылкой только заголовок и растянуть её
  `::after` на карточку, а теги поднять `z-index`.
- **Вес ассетов.** `src/assets` — 43 МБ, `hero-poster.png` — 4.8 МБ. Кандидаты
  на WebP/AVIF и ресайз.
- **Календарь** — 14 дат захардкожены, стрелка не листает (нет JS).
- **Теги в фильтрах** — нет состояния «активный».
- **`<head>`** — нет `meta description`, OG, favicon.
- **Не закоммичено**: `event-card`, `events-list`, правки `events`, `main.scss`
  и более ранние `afisha`/`calendar`/`categories`/`tag`.

## 9. Соглашения

- Разметка блока — только в его `.html`, стили — только в его `_*.scss`.
- Элемент (`span`/`button`/`a`) задаётся в файле компонента, а не в месте вызова.
- Данные — пропсами, произвольная разметка — блоком `{{#> component}} … {{/component}}`.
- В HTML-комментариях **не писать** примеры Handlebars: `{{#>` внутри `<!-- -->`
  исполняется и ломает сборку. Для комментариев самого Handlebars — `{{!-- --}}`.
- Числа в CSS — из макета, с комментарием, откуда взяты.
