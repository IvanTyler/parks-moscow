# Парки Москвы — заметки по тестовому заданию

Вёрстка главной по макету Figma (копия `fNoCrQg6XHBPFKR8MEWzhW`, узел `1:7685…`), десктоп.
Стек: Vite 5 + `vite-plugin-handlebars` (партиалы), SCSS, Swiper 11, чистые ES-модули. Без jQuery и сборщиков вроде «полотна».

```bash
npm i
npm run dev      # http://localhost:5173
npm run build    # dist/
npm run preview
```

---

## 1. Что готово

- Шапка: топбар (подкасты, поиск, панель доступности) + основной уровень с меню и логотипом.
- Крошки — **отдельный партиал вне `<main>`** (`src/components/breadcrumbs`), на главной пустой.
- Все 9 секций: hero, «В центре внимания», «Где заняться хобби», «Афиша мероприятий» (теги, календарь, карточки), «Выберем ваш Парк Москвы?» (округа/интересы/пины), «Новости», «Онлайн-журналы» (Swiper, 2 слайда), «Парки Москвы» + подписка, «Партнёры».
- Подвал — **вне `<main>` и вне контейнера контента**, прижат к низу страницы (`body` — flex-колонка, `main { flex: 1 1 auto }`).
- Компоненты вынесены: `button`, `tag`, `social-link`, `subscribe`, `feature-card`, `hobby-card`, `event-card`, `events-list`, `afisha`, `calendar`, `categories`.
- Шрифты PT Root UI подключены (см. п. 3).
- `<head>`: title, description, favicon, OG-теги.

Правила раскладки: `.container` — `max-width: 1920px; padding: 0 120px` → контент 1680, как в макете.
Соглашение по блокам: `src/components/<блок>/<блок>.html` + `_<блок>.scss`, подключение `{{> блок}}`, стили — через `@use` в `src/styles/main.scss`.

## 2. Осталось сделать (план на завтра)

### [ ] 1. Вес картинок — главная проблема

В `dist/assets` ≈ **43 МБ** PNG на 21 файл:

| файл | вес |
|---|---|
| `hero-poster.png` | 4,7 МБ |
| `yoga-autumn-sky.png`, `golden-autumn-weekend.png`, `excursion-autumn-alleys.png` | по ~2,4 МБ |
| карточки «В центре внимания» / «Афиша» / «Новости» | 1,5–2,4 МБ каждая |

План: перегнать в WebP (q≈82) или AVIF, это даст −85…90 %; `hero-poster` — в первую очередь, он же LCP.
После замены проверить, что в разметке остались `width`/`height` (иначе поедет CLS), и что `loading="lazy"` есть у всего, кроме первого экрана.

### [ ] 2. Обложка для соцсетей

`og:image` не задан специально: нужна картинка 1200 × 630. Положить в `public/` (папки пока нет) и добавить тег — иначе превью в мессенджерах будет пустым.

### [ ] 3. Inter для дат

В макете дата в карточке события набрана Inter 16/20.8, у нас PT Root UI и метрика округляется до 21px (`src/components/event-card/_event-card.scss`, комментарий у `__date`). Решение: либо притащить Inter 400, либо оставить PT Root UI и зафиксировать как осознанное отклонение.

### [ ] 4. Проверка в браузере на 1440 и 1920

Headless-браузер в этой среде не запускается (падает на named pipes), поэтому всё проверялось статически: по собранным CSS/HTML/JS и по числам из Figma. Нужен проход глазами:

- «В центре внимания» — карточки 544×680, чётные сдвинуты на 51px и повёрнуты на 4°, ряд уходит за правый край; снизу 99px, чтобы низ не срезался.
- «Онлайн-журналы» — ровно 2 слайда, на последнем нет «доезда» на пол-карточки (правили `slidesPerView`).
- «Партнёры» — лента листается по кругу и тянется мышью; на 1920 в DOM 12 ячеек (вторая копия `aria-hidden`).
- «Парки Москвы» — плашки соцсетей в две строки (570 / 510), поле e-mail с рамкой только снизу, ошибки валидации не сдвигают кнопку.
- Подвал — белый логотип в тёмной карточке, три колонки меню, соцсети по центру нижней строки.

### [ ] 5. Доступность

- `:focus-visible` для стрелок-кружков и ссылок в карточках.
- Skip-link «к содержимому».
- `prefers-reduced-motion` — сейчас у Swiper в hero автоплей, стоит выключать.

### [ ] 6. Сопроводительное письмо

Зафиксировать решения, которые проверяющий ищет по ТЗ:

- Крошки, меню и подвал физически разведены с контейнером динамического контента (см. комментарии в `index.html`).
- Никаких «неопознанных» скриптов: только свои модули + официальный Swiper. Сторонних селект-плагинов нет.
- **select2 не понадобился**: «Все парки Москвы» в макете — не `<select>`, а кнопка сброса фильтров (`data-map-reset`), нативных селектов на странице нет вообще.
- Открытые события вместо магии внутри плагинов — список ниже.
- Валидация e-mail своя, на регулярке, без плагинов.

### [ ] 7. Мелочи

- Мобильная версия: ТЗ десктопное, в блоках есть только брейкпоинт `1024px` и он не выверен по макету.
- `theme-color`, `manifest` — не нужны для теста, но в проде пригодятся.
- Проверить ссылки меню (сейчас `href="#"`).

## 3. Шрифты

- Файлы: `src/assets/fonts/pt-root-ui-{regular,medium,bold}.woff`, по 60 КБ, 798 глифов, кириллица проверена скриптом (включая `ё`, `—`, `«»`, `№`, `₽`).
- Подключение: `src/styles/_fonts.scss` → `@font-face` 400 / 500 / 700, `font-display: swap`; `@use 'fonts'` первым в `main.scss`.
- Семейство в `_variables.scss`: `$font-main: 'PT Root UI', Arial, sans-serif`.
- **Источник — CDNFonts (свободная версия ParaType).** Для тестового задания ок, для прода нужно подтвердить лицензию или взять файлы у дизайнера. Пометить в письме.
- Vite сам кладёт их в `dist/assets` с хешем — руками ничего прописывать не нужно.

## 4. События для интеграции

Все события всплывают (`bubbles: true`), слушать можно на `document`:

| событие | где | detail |
|---|---|---|
| `journals:ready` | `src/js/journals.js` | — (слайдер инициализирован) |
| `journals:slide-change` | `src/js/journals.js` | `{ index }` |
| `partners:scrolled` | `src/js/partners.js` | `{ index, total }` — первый видимый логотип |
| `subscribe:subscribed` | `src/js/subscribe.js` | `{ email }` |

```js
document.addEventListener('subscribe:subscribed', (event) => {
    // здесь будет отправка на бэкенд
    console.log(event.detail.email);
});
```

## 6. Известные ограничения

- Лента партнёров на 1920 копирует ячейки (6 → 12), чтобы работал круг. Вторая копия `aria-hidden` и без `tabindex`.
- «Онлайн-журналы»: `slidesPerView: 2` целым числом — иначе Swiper добавляет лишний «доезд» до последнего слайда.
- `.container` рассчитан на 1920; ниже 1024 поведение не выверено по макету.
